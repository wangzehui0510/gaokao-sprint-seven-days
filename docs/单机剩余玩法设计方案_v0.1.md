## 一、每日属性点与每日NPC加点

### 已确认方案（2026-11-10）：每天08:00发放；离线时在08:00后上线补上

- **发放时刻**：局内`day >= first_daily_attribute_day`且真实跨越`daily_attribute_time`（08:00）时，四名角色各获得`daily_attribute_points`点。
- **离线补发**：`load_file()`恢复后，把当前时刻之前所有已错过且未发放的`08:00`检查点一次性补发（每天各`daily_attribute_points`点）；开发时钟语义的`load_file_at_time()`按目标时刻同样补发，保证"八点后上线补上"。
- **幂等**：存档保存`daily_points.granted_days`（升序整数数组）。开发时钟回退到已发放日不再发；前进到未发放日按当前配置值发放。热改只影响之后未发放的日期，不回改已发放点数。
- **本人**：点数进入`unspent_points`，人物页现有“+”入口消费；不自动分配。
- **NPC**：同刻各得1点并**立即消费**（NPC不保留待分配点），按固定轮换`["attention","discipline","health","intelligence"]`循环，`npc_growth.cursor`随存档；不抽随机数。三份预设8点消费完后继续按轮换分配，不改写预设来源。
- **界面**：班级详情页新增属性面板，显示每名角色的属性与待分配点，有待分配点时可直接加点（含NPC由AI轮换显示，不需要手动）。
- **飘字**：发放时刻（在线跨越或离线补发）在教室场景飘字提示“已获得属性点+1”。
- **边界**：第7天16:40终局后不再发放；终局同刻已跨过08:00则按已发生处理；v5旧档迁移不补历史，迁移日视为已处理。
- **日志**：每次发放写一条班级级日志“第N天发放属性点+1”；NPC分配写“某某：自律性+1”。

## 二、抢答`answer_challenge`

配置已具备：`pair`、`scene=classroom`、120秒、启动本人-4专注、双方每分钟-1专注/-0.3体力、胜者+6专注、平局各+3、败者`discouraged`、`knowledge_multiplier=0.5`、`source=school`、完成事件`resolve_answer_challenge`。

### 已确认方案（2026-11-10）：按考试同构公式判定；胜负专注数值可配置

- **可用条件**：当前为文化课（`kind=="lesson"`且科目为语/数/英）；双方均在教室；发起者专注不低于启动费用。音乐/美术同在教室但无知识，必须显式排除，不能只看`scene=classroom`。
- **判定**：`score_i = K[科目,i] × (1 + C × 有效智力_i)`，`C`读`exam_intelligence_coefficient`（当前0.03）。比较双方`score`；相对差`≤ 1e-13`判平局（与项目既有浮点容差口径一致，不新增常量）。
- **结果结构**：复用掰手腕的`{"outcome","winner_index","loser_index"}`写入`interaction.result`，不新建第二套判定结果。
- **知识**：双方各按当前科目课堂速度的0.5倍累计，来源`school`，进在校日榜与总知识（与动作表`knowledge_source=school`一致）。
- **收益**：完全读现有效果表（胜/负/平），代码不硬编码数值；业务确认败者改为减少专注（数值在效果表`value`可配置），胜者增加专注，替换原`discouraged`方案。
- **打断**：整体打断，不发判定奖励，已产生的知识保留；旧搭档按现有规则回课表。
- **历史**：判定参数与结果随互动存档；完成后热改费率不重算。
- **范围**：`source=player`，不加入任何NPC自主池；不掉物品、不产生违纪。

| 新增`_resolve_answer_challenge()` | 计算双方分数、写`result`；与`_resolve_arm_wrestle`共用结果校验 |
| `_validate_result`/存档校验 | 允许`answer_challenge`的`result`，校验胜/负下标互斥且平局时为-1 |
| `phase_scope.json` | 把`answer_challenge`加入`enabled_actions`（当前54→55） |
| `main.gd` | 互动页与右键“更多…”并列一项；结果提示复用现有互动结果文案，增加“抢答”分支 |
| `classroom_view.gd` | 复用现有双人方向与完成提示，不做新动画 |

### 备选

- **B 知识优先再比智力**：先比本科知识，相同再比有效智力，仍相同平局。更直观但会把抢答变成“知识领先者的确定性胜利”，缺少智力翻盘空间。
- **C 暂缓**：保留54项动作，抢答继续标记未完成。

### 验收要点

公式数值与平局容差、四科各自取值、非文化课与课间不可用、双人在不同地点不可用、启动费用不足拒绝、打断无奖励、知识归属与倍率、存档往返、热改不追溯、终局禁入、与六项竞争自主池互不影响。

## 三、延期自主行为

### 3.1 课间磨蹭（已确认：触发后离开教室，四地点各按一种现有动作）

现状：`auto`来源、180秒、`scene=any`、无知识、每分钟+1%最大专注/+0.3%最大体力、违纪`distraction`，仅缺触发策略。

已确认（2026-11-10）：课间开始时，当角色专注低于`35%当前上限`时，以`35%`概率触发磨蹭；触发后角色**不在教室**，从四个地点动作中抽取一个：教室自习、操场、食堂、宿舍，每个地点先按一种现有动作执行（复用其现有效果表，不同地点自然产生不同影响）。地点抽取走独立随机流；课间结束强制中断并接课表。

- 玩家入口：不开放（保持`source=auto`）。
- 日志：记录“课间去某处磨蹭”，不产生知识。
- 宿舍动作若限`dorm_free`时段，需在权威表中放宽该动作的课间可用性（实施时明确并列出）。

### 3.2 纸条（已确认：不做自动纸条）

业务确认（2026-11-10）：纸条是玩家之间的游戏内交流互动，保留玩家主动入口，**不开放NPC自动纸条**。`deferred_auto_actions`中的`send_note`保持后置清单原状（不启用），实施清单中“自动纸条”项改为“不做”。

## 五、特殊事件

### 推荐框架

- **开关**：沿用`events_enabled`，默认`false`；确认后改为`true`才进入本次范围。
- **触发点**：早晨上课前（第2-7天08:00）、午休、放学（16:40）三个时刻；每个时刻以`event_chance`（建议0.25）走`ambient_rng`抽取，每日至多1个事件（可配置，属体验节奏而非防错上限）。
- **结构**：权威表`events`（id/名称/触发点/权重/选项组）+ `event_options`（文本/效果/日志文案）。效果复用现有effect结构（resource/apply_buff/待新增`attribute_point`），属性成长统一以“待分配点”给出，不直接改基础属性。
- **记录**：`events_log`（day、clock、event_id、option_id、实际结算值）入存档v6，日志页可见；局末16:40后不再触发，进行中的事件按普通状态收束。
- **一致性**：事件导致的属性点/资源变化与现有规则一样只影响之后结算，不重算已冻结考试与已发布日榜。

| 忘带作业 | 早晨 | 坦白：专注-6；课间补：课间强制`notes`动作；借同学的：触发一次`borrow_notes` |
