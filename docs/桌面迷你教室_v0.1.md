# 桌面迷你教室

版本0.1，2026年11月6日。已确认采用方案1：放在桌面角落的独立迷你教室，延续斜俯视正交与复古像素风格。本文记录目标设计，**不代表已完成接入**；完整现状与换机接续步骤见`继续开发交接.md`。

## 当前实现状态

- `ClassroomView`的黑板点击、真实状态标签、1x/2x几何与动画节流已完成独立检查。
- 窗口管理器和桌面项目设置已写入，主界面`main.gd`仍是旧布局，尚未调用窗口管理器或连接黑板课表入口。
- Godot主窗口直接`hide()/show()`存在引擎限制；原生验收失败，关闭进托盘与恢复尚未完成。
- 以下窗口、面板、关闭和退出行为都是已确认的目标。当前项目设置与旧布局不匹配，不能当作可用桌面版交付。

## 目标窗口与布局

- 默认以1倍显示384×256教室，顶部工具栏和底部行动栏各32像素，主窗口内容为384×320。
- 2倍显示时教室为768×512，工具栏和行动栏保持独立文字排版，主窗口内容为768×576。
- 点击角色后在教室左侧展开292像素详情面板，间隔8像素；展开后1倍为684×320，2倍为1068×576。人物、课表、班级记录共用这个临时面板。
- 首次打开定位到屏幕工作区右下角，之后记住位置、像素缩放和置顶偏好。窗口拖动入口位于顶部课程和时间区域。
- 教室和角色以整数倍显示；界面文字使用清晰的独立字号。1倍和2倍都必须验收文字、按钮、人物、课表的完整显示。

本轮保留现有四张课桌和专用坐姿素材。四名角色目前仍共用同一外观，由姓名和选中提示区分。教室之外的地点以真实位置文字显示，操场、宿舍等完整画面继续后续制作。

## 目标关闭、托盘与真正退出

用户已确认关闭行为：点击关闭按钮或系统关闭请求后，窗口收进Windows托盘，游戏进程与四人自主活动继续运行。恢复入口位于托盘图标和托盘菜单。

真正退出位于托盘菜单。退出先保存当前正式局或开发局，保存失败必须显示错误并保留现场，不能把未保存的状态表现为退出成功。

“窗口已隐藏”和“游戏已经退出”具有不同的时间语义：

- 窗口隐藏到托盘期间仍在线，动作、课表、消耗、恢复和自动保存按实际运行时间继续。
- 进程真正退出期间不推进；下一次启动按电脑当天日期与时间重新对齐课表，不补算离线收益。
- 隐藏时可以停止绘制人物动画，但不能据此暂停模拟器或按帧数少算收益。
- 电脑锁屏、休眠和唤醒的实际行为需要独立原生验收，本轮窗口改造不新增一套离线收益规则。

窗口偏好保存到`user://desktop_settings.json`，与`classroom_save.json`、`classroom_debug_save.json`分别保存。窗口位置和缩放不进入Excel动作数值表。

## 目标场景与操作

- 点击自己的角色或顶部人物入口查看自己的状态。
- 点击任何同学只改变查看对象，不改变玩家控制索引；底部专注、休息、睡觉始终控制自己。
- 点击黑板或课表入口查看由正式JSON配置生成的当天课表。
- 班级记录只显示真实执行器产生的动作与配置记录。
- 专注每次点击生效，学习中重复点击也增加专注并重新建立学习段；基础休息仍免发动成本。
- 配置错误、存档错误、托盘初始化或偏好保存失败必须明确报出，不静默使用默认成功状态。

本轮复用四人共享行为树、真实课表、动作执行器和Excel导出的JSON。窗口管理器只管理系统窗口及偏好，不持有第二份游戏状态，不自行结算知识或资源。后台服务器、真人联机、道具互坑和特殊事件不在这次窗口改造范围内。
