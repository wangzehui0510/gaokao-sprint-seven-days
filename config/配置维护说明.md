# 配置维护说明

版本：0.2.0。首版数值属于可调整草案，已确认的玩法规则见项目策划文档。

## 日常维护

1. 打开 `outputs/01a1aebc-daa9-7ca0-9b2c-d4652fa3194d/高考冲刺七天_配置_v0.2.xlsx`，修改后保存。
2. 在项目目录运行 `& .\tools\导出配置.ps1`。
3. 看到“已导出”后，使用新的 `config/game_config.json`。游戏接入阶段应读取这份导出文件。

导出失败会明确打印工作表、Excel行号、字段和原因，退出码非零，保留上次成功的JSON；旧文件的存在不代表本次导出成功。不能在报错后继续把旧配置当成本次结果发布。

工作簿换了位置时，运行：

```powershell
& .\tools\导出配置.ps1 -WorkbookPath 'D:\你的目录\配置.xlsx'
```

脚本默认使用本机配套Python运行时。其他机器需要安装Python 3.10或更高版本，并明确指定：

```powershell
& .\tools\导出配置.ps1 -PythonPath 'C:\Python313\python.exe'
```

也可直接调用无第三方依赖的导出器：

```powershell
python -X utf8 .\tools\export_game_config.py '配置.xlsx' --schema .\config\config_schema.json --output .\config\game_config.json
```

## 表格约定

- 第3行为中文列名，第4行为英文机器字段，第5行开始是数据。保留工作表名、第4行字段名称及列顺序；可以增加、删除或排序数据行。
- 浅黄色单元格为数值输入。所有消耗、恢复、启动费用、完成奖励、物品数量、持续时间均以表内值为准。
- `0`表示明确的零；空白表示该类型不适用。必填项不允许空白。瞬时动作两列时长必须留空。
- 布尔值使用Excel逻辑值TRUE/FALSE，或填写文字`TRUE`/`FALSE`。导出时为JSON布尔值，不接受文字“是/否”。
- ID是表间引用，须唯一且无首尾空格。更改ID时同步修改所有引用；显示名称可以单独调整。
- 配置输入不能使用公式。“数值验算”页允许公式，但不导出，也不参与运行数据。
- 新增已有类型的动作可直接加行；新增字段或新的条件、事件、效果类型，需要同步修改字段契约、导出校验与后续游戏执行器，不能只在表里创造一种新枚举。
- 不要重新运行首版工作簿生成脚本覆盖手工调好的Excel。后续维护以Excel为源，JSON为导出结果。

## 各表职责

| Excel表 | JSON键 | 维护内容 |
| --- | --- | --- |
| 动作 | actions | 来源、对象、场景、时长、知识倍率、违纪标记、完成去向、启用开关。 |
| 动作效果 | effects | 一个动作的多条资源、状态、物品、事件或后续动作效果。 |
| 临时状态 | buffs | 临时属性、知识倍率、知识重定向、持续时间和互斥组。 |
| 物品 | items | 名称、说明、是否消耗与是否跨日保留。 |
| 每日物品奖池 | drop_pool | 物品引用、单次抽取权重、数量和启用开关。 |
| 自主开小差池 | auto_pool | 候选动作、权重、时段、目标与可支付条件。 |
| 动作打断规则 | interrupt_policies | 已发生效果保留、费用和物品是否返还、剩余搭档去向。 |
| 科目 | subjects | 知识速度、考试满分、曲线参数、默认动作、考试知识来源。 |
| 课程表 | schedule | 七天各七节课的科目与时段引用。 |
| 时段 | periods | 每天的起止时间和默认活动，午餐与午休分别配置。 |
| 参数 | globals | 初始资源、属性换算、阈值、成长、每日抽取件数等。 |
| 数值验算 | 不导出 | 调整示例属性，查看理想学习知识与考试公式的结果。 |

中文表名以交付工作簿和`config_schema.json`为准。JSON格式为`{version, schema_version, tables}`，每张表导出为记录数组；空白的不适用字段输出`null`。

## 动作与效果字段

`duration_min_s`与`duration_max_s`的单位为秒，持续动作每次启动在该区间抽取时长，相等时为固定时长。实际执行可被打断或课程边界截断。瞬时动作使用`kind=instant`，两列时长留空；举报和专注指令均为此类型。

| 字段 | 值与含义 |
| --- | --- |
| phase | start发动时；tick执行中；complete正常完成时；instant瞬时结算。 |
| recipient | self发起者；target目标；both双方；ally盟友；winner胜者；loser败者。 |
| type | resource资源变化；apply_buff施加状态；consume_item消耗物品；start_action进入后续活动；event业务事件。 |
| resource | focus当前专注；stamina当前体力。健康是属性，不是体力资源。 |
| mode | flat固定点数；max_ratio当前上限比例。 |
| value | 资源消耗为负、恢复为正；物品消耗数量为正。0.02表示上限的2%。 |
| period_s | tick效果的计量周期秒数；60表示value为每分钟变化量，其余阶段留空。 |
| max_basis | max_ratio填写current，以发生当时的资源上限计算；flat留空。 |
| sequence | 同一动作同一阶段内的执行顺序，不能重复。 |
| condition | always每次；natural_entry自然入段；course_active实际课程时段；winner/loser/tie对应胜负结果；selected_variant选定变体。 |
| next_action_id | 后续动作ID；current_course为当前课表课程解析器。 |
| event | forced_entry强制入段；close_violation关闭本次违纪；deliver_note送达纸条；resolve_answer_challenge/resolve_arm_wrestle结算胜负；interrupt_reading打断阅读。 |

持续资源变化按实际秒数积分：`value × 实际秒数 / period_s`，max_ratio再乘当时上限。时间经过后才产生对应收益；完成型效果不会因被打断而提前发放。知识增长由科目速度、专注力系数、动作与状态倍率、疲劳倍率共同决定。

专注指令的`+5`效果条件为always，进入课程的效果条件为course_active；非上课时仍可成功加专注。课程中每次点击重新抽取学习段，已在学习时同样生效，没有冷却。自然学习入段扣1的效果条件为natural_entry，不重复向指令强制入段收费。

举报不打断举报者当前动作；关闭目标违纪并让目标强制进入当前课程。2026年11月7日确认例外：若目标就是举报者当前双人互动搭档，整体结束该互动，目标强制回课程，举报者按课表正常重新选择；未完成纸条不送达。执行器按违纪事件ID保证同一事件只结算一次，不能改成按天限制举报次数。

阶段3的业务事件契约：纸条必须有且只有一个`always`条件的`deliver_note`完成事件；举报必须有且只有一个`always`条件的`close_violation`瞬时事件，最后再无条件强制进入`current_course`。改变这些条件或顺序会在加载时明确拒绝，避免已完成却未送达或尚未关闭违纪就重选活动。资源数值、持续费率与下一次动作时长仍可按既有规则调表。

## 每日物品参数

四人各自每天首次实际成功开始当前课程时，按`daily_item_draw_count`抽取`drop_pool`奖项，并将每次的`quantity`加入该角色背包。当前配置抽取3次，`daily_item_with_replacement=true`允许抽到同一奖项。睡觉、发呆和非课程动作不触发；旧档不补历史，领取日由v4存档持久保存，迁移v3时原领取日保留。

抽取次数和每行数量必须为正整数，允许重复参数必须声明为布尔值。只有启用且权重大于0的奖池行参与，权重总和必须为正有限数；不放回时按奖池行抽后移除，有效行数必须足够。无效配置在加载或热更新入口明确拒绝，数量溢出在整份奖励入库前报错，不产生部分物品或领取成功记录。修改奖池不重发当天已领取奖励，后续符合条件的新领取使用新配置。

## 时间、状态与版本

阶段5入口校验：`exam_intelligence_coefficient`须为非负数字，`score_decimal_places`须为非负整数；知识科目的`max_score`、`score_scale`须为正有限数，考试科目的`knowledge_subject_id`须引用知识科目。当前配表仍为智力系数0.03、单科保留1位小数。先对各科四舍五入，再以共同整数刻度求总分；刻度与总分仅受实际数值表示范围限制，不另设业务分数或小数位上限。

七天主流程已接入开考快照、课程结束发布、四科日榜与最终榜。纯计分工具保留当次知识、有效智力与公式参数供复算；有效智力为负仍按原公式计算，不增加静默钳制。已快照科目不使用后续配置重算，界面逐科显示保存的小数位；总榜保留共同精度。成绩整数刻度在JSON中编码为十进制字符串，不能用普通JSON数字替换而丢失大整数精度。

完整课表必须覆盖`session_days`与课程时段，日/时段和课节标识不能重复，不能引用非课程时段或相互重叠的课程时段。末日须有三科知识考试，不得提前安排考试或缺少科目；允许三科考试在合法课节间置换。日榜截止取当天最后课程结束，体育取末日第一场考试开考，最终榜取末日最后课程结束；当前权威JSON对应16:40、14:00和16:40。

热改保留已发生事件及其时刻，只更新尚待事件。若新课表把尚待日榜、开考或终局移到已经观察过的时刻之前，整次更新明确拒绝，不能补造历史。局内天数与已建立知识科目身份不能热改；未来合法时刻、费率和未取值科目的公式参数仍可调整。跨配置读档先完成同类规划再覆盖当前有效局，失败保留原局。

v4存档保存退出时知识、有效智力和公式参数。恢复跨过纯榜单/考试边界时使用保存的冻结来源，不能静默换成当前新配置；退出期间不学习、恢复、发奖或送纸条。v1至v3旧档缺历史明确标注“未记录”，迁移当天只统计接入后的知识；缺开考快照不补零总榜。完整规则见`docs/阶段5实施方案_v0.1.md`。

时段起止在Excel中显示为`hh:mm`，底层是Excel原生时间数值。JSON保留一天的比例，例如08:00为`1/3`；读取后乘86400得到相对当天零点的秒数。本地局使用电脑时间，服务器统一时区仍待联机阶段确认。

状态`lifecycle=action`随所属动作结束移除，持续秒数留空；`timed`按独立到期时间移除。同组`stack_group`按`stacking`处理，错误课本普通版和强化版同组替换，不叠加智力惩罚。

特殊事件参数`events_enabled=false`。两项未确认扩展动作使用`enabled=false`保留，不会进入首版可用动作。本地阶段已确认支持运行中热更新：重新读取导出的JSON后，后续消耗与恢复立即采用新费率，当前已抽取的动作时长保持不变，不重复收取启动费；关闭游戏期间不补算收益。操作、存档和阶段范围详见[Godot开发路线](../docs/Godot开发路线_v0.1.md)。
