# Godot 开发路线

版本0.2，2026年11月6日。阶段1和阶段2已完成当前范围，建立可运行的本地Godot工程；本文件同时说明当前运行方法、实际范围和后续路线。

## 已确认方向

- 首发Windows桌面横屏；本机Godot实际版本为4.7.2 stable。
- 先完成本地单人操作版，后台服务器与真人联机后续开发。
- 教室内四名角色共用一套行为树，全部自主活动，各自拥有独立运行状态。
- 玩家只向自己的角色下主动指令，可以选择同学作为互动对象。
- 继续采用现有策划、Excel导出的JSON和斜俯视正交像素素材。
- 新局按电脑当前时间进入课表；读档重新对齐电脑日期与时间，关闭期间不补算收益。
- 导出的配置可在运行中重新读取，后续消耗与恢复立即使用新值，已抽取的动作时长保持不变。

## 启动与操作

当前工程文件为项目根目录的`project.godot`，主场景为`scenes/main.tscn`。已在本机Godot 4.7.2 stable执行编辑器导入和真实规则检查。

在`D:\挂机上课`打开PowerShell运行：

```powershell
& .\tools\start_game.ps1
```

进入Godot编辑器查看工程：

```powershell
& .\tools\start_game.ps1 -Editor
```

启动脚本默认使用`D:\Godot_v4.7.2-stable_win64\Godot_v4.7.2-stable_win64_console.exe`。更换安装位置时显式指定，不会自动搜索或改用其他版本：

```powershell
& .\tools\start_game.ps1 -GodotPath 'D:\Godot\Godot_console.exe'
```

游戏默认窗口为1280×800，最小1200×760。顶部显示课程、日期和时间；右侧名单与角色面板可查看四人状态；底部记录实际动作事件。

- 点击教室角色或右侧名单，只改变查看对象。
- “我的行动”中的专注、休息、睡觉始终作用于自己的角色。
- 专注每次点击均按配表增加专注；上课中重新进入当前课程并抽取新动作时长，学习中重复点击也生效。
- 右上角“保存”立即写档；“···”菜单提供重新读取配表、重新开始和开发工具。
- “重新开始”需要界面确认，随后创建新班级并替换正式进度。

正常开局若正处于晚上或课外时段，角色会依课表休息。观察上课循环可使用下面的开发时钟，不需要修改电脑时间。

## 开发时钟

打开“··· → 开发工具”，点击“开发时钟：第1天 08:00”。入口先保存正式进度，再建立独立的第1天早课测试局；顶部会显示“开发时钟”。

填写“推进分钟”后点击“推进”，会经过正常执行器完成时间积分、动作结束和课表切换。该入口不直接赠送知识、资源、奖励或伪造事件。开发时钟仍会随程序实际运行时间继续走动。

点击“回到电脑时间”会保存开发局，再读取正式存档并对齐当前电脑时间。开发局与正式局分文件保存；开发入口每次建立新测试局，不自动恢复上次开发局。

## 配表与热更新

数值源为`outputs/01a1aebc-daa9-7ca0-9b2c-d4652fa3194d/高考冲刺七天_配置_v0.2.xlsx`，游戏实际读取`config/game_config.json`。字段和导出规范见`config/配置维护说明.md`；运行中的生效策略以本节为准。

1. 修改并保存Excel；当前已接入动作的时长、消耗、恢复和知识速度均可由配表调整。
2. 在项目根目录执行`& .\tools\导出配置.ps1`，确认导出成功。修改Excel本身不会触发游戏更新。
3. 游戏每约1秒检查JSON修改时间，也可点击“··· → 重新读取配表”。成功后状态栏显示“配表已更新”，班级记录写入配置变化。
4. 后续结算立即采用新费率。已有动作不重新扣启动费、不重新抽时长；已发生的收益与结果不重算。时长区间变化作用于下一次启动的动作，资源上限变化按新上限调整当前资源。

`config/phase_scope.json`单独声明阶段1/2允许的内容；完整Excel中尚未接入的动作不会因为导出而自动开放。新增效果类型、互动流程或场景需要同步开发执行器与表现，不能只新增配表行就当作已实现。

导出器或游戏读取配置失败会明确报错。导出失败时旧JSON仍在，但不代表本次修改成功；游戏读取失败时停止结算并显示错误，修正后可从菜单重新读取，不会静默套用一套默认数值。

## 存档语义

- 正式进度为`user://classroom_save.json`，开发进度为`user://classroom_debug_save.json`。Windows默认目录为`%APPDATA%\Godot\app_userdata\高考冲刺七天\`。
- 运行中约每30秒自动保存，正常关窗前也会保存；可随时点击“保存”。异常结束只保留最后一次成功写入的状态。
- 保存四人状态、已抽动作时长和剩余执行进度、随机状态、状态到期时间与日志。读档不重新抽当前动作，不重复扣启动费。
- 读档按本局创建日期计算第几天，再对齐电脑当前时刻。关闭期间不补资源、知识或完成奖励；若已跨课，旧动作按打断处理，再由行为树选择当前时段动作。
- 同一课程内重新打开时保留已存动作的剩余执行进度；关闭的时间不计入该动作执行时长。
- 当前局不锁定旧配置。读档使用当前有效配置的后续费率，保留已发生结果与已抽时长；不兼容或损坏的存档会明确报错，不伪造新局作为读取成功。

## 第一阶段的目标

做出一个能持续运行、能看懂、能操作、能保存的教室版本。首先验证“自主学习→开小差/恢复→被互动打断→回到课表”的实际循环。

先以一个正常课程窗口完成纵向验证，再扩展全天和七天流程。首轮不要求52个动作全部完成，不以四个场景同时铺开作为开工目标。

## 工程组织

工程直接位于现有项目目录，复用`assets/`和`config/`。核心规则在`scripts/core/`，行为树适配在`scripts/ai/`，界面在`scripts/ui/`；`tests/test_core.gd`使用正式配置和真实行为树检查规则。

当前采用GDScript、2D场景与Compatibility渲染器。Beehave已固定为2.9.3并保留MIT许可证；来源与调试协议兼容修正记录在`addons/beehave/SOURCE.md`。

| 模块 | 负责什么 |
| --- | --- |
| 配置读取 | 读取`config/game_config.json`，校验字段、引用、枚举和版本，错误明确报出。 |
| 游戏状态 | 保存四人的属性、资源、知识、背包、临时状态、当前动作，以及班级与课程状态。 |
| 游戏时钟与课表 | 提供统一时间、课程边界、当天到校及换日事件；开发测试可显式推进时间。 |
| 共享行为树 | 在自主决策点选择动作，运行中的动作继续返回RUNNING。 |
| 动作执行器 | 统一执行校验、启动、持续结算、完成、打断和互动参与者转移。 |
| 存档与记录 | 保存真实状态、随机抽取结果和事件记录；读档不重新扣启动费或重复结算。 |
| 场景与界面 | 根据状态展示角色、动画、资源、课程、操作入口和互动记录。 |

规则层通过明确接口接收指令、产生状态变化，不直接依赖精灵、按钮或动画。以后服务器可以接管规则与状态，客户端继续负责显示和输入。这是职责划分，第一阶段不搭建网络框架。

## 四人共用行为树

共享的是行为树定义；四个角色分别运行各自的树实例和黑板。黑板保存角色ID、目标及决策上下文，资源和背包以角色状态为唯一来源，不复制为另一份权威数据。

行为树不是数值执行器，不自行扣资源、发奖励或操作动画。行为树选择动作后向统一执行器提交请求；玩家的主动指令也提交到同一入口。

自主流程沿用现有策划：

1. 课表边界、动作完成或合法打断先更新当前动作状态。
2. 当前动作仍有效且执行中，继续执行，不重新抽时长或随机候选。
3. 到自主决策点时解析当前课程/时段；知识课按体力、专注等规则选择睡觉、开小差或学习。
4. 音乐、美术及非上课时段按既有恢复与课表规则执行。

学习段的5～10分钟只在启动时抽取一次。专注严格低于50的判断发生在自主决策点，不能每帧用阈值强制重开动作。

玩家每次点击专注，执行器按规则结算旧动作、增加专注并建立新的课程活动段。行为树读到这个运行中的动作后继续执行；无需新增冷却、保护时段或手动锁。合法互动和课程边界仍能打断。举报仍是瞬时动作，不占用举报者的持续动作。

其余三名同学先按已确定的课表与自主规则活动，并真实参与玩家发起的互动。自主发起哪些双人互坑、目标如何选择及频率，属于待补充的AI策略，不在开发时暗中添加。

## 首轮必须保留的玩法语义

- 健康是属性，体力是资源；最大专注依自律性，最大体力依健康。
- 动作时长、消耗、恢复、发生阶段和比例均读取配表，不在行为树节点写死数值。
- 发动、持续、完成、瞬时分开处理；只结算真实执行的时间。
- 基础休息免发动成本，不能另设避免资源耗尽的隐式赠送或恢复路径。
- 专注指令每次生效，学习中重复点击也重新抽时长；不重复收自然入段费。
- 学习知识只在有效知识课程窗口增长，音乐与美术只按恢复课程规则处理。
- 随机时长、当前动作、参与者和已结算时刻需要入档，不能读档后重新抽取。
- 配置错误、物品不足和动作不满足条件必须可见，不能静默换动作或显示假成功。

## 后续优化

- 可读性：主动方、目标、物品飞行、被打断原因、完成结果有明确表现。
- 趣味性：确认后加入同学主动互坑的AI策略、不同自主偏好和连锁反应；继续共用行为树，差异来自数据。
- 表现：更多外观、动作循环、音效、表情和场景细节。
- 内容：其余已确认动作、完整操场/食堂/宿舍；特殊事件另行确认后制作。
- 性能：根据实测降低空闲渲染和不必要的树更新，持续结算仍以真实经过时间计算，不能因低帧率少发收益。
- 工程：配置验收工具、动作与存档回归验证、打包发布流程。
- 联机：服务器权威时间、状态持久化、房间与邀请、重连恢复、事件顺序、重复请求处理。

商店、货币、复杂社交大厅等尚未确定的系统不列入当前开发范围。
